# Pending Tests

## v0.18.1 — selective upstream update

- Independent candidates: dragging must keep the same node ID. Editing prompts or generation settings, opening/canceling image tools, and creating cropped/masked/split/upscaled/angle results must preserve the source placement and batch. Editing the requested size must not reshape an existing placement. Only replacing its actual media should detach it; prompt/config overrides must survive reopening the project.
- Canvas navigation: keep Select as the default; in Move mode, background dragging pans while real nodes still move normally. Root double-click toggles the batch, candidate double-click previews, and resizing hides the lower prompt panel only until release.
- References: the normal and expanded prompt editors should preview connected resources and support continuous canvas selection with “+”; Escape/Done returns to the target. Group members resolve real placement resources without duplicating the root's primary mirror. Removing a group reference must use the explicit whole-group control, not an individual thumbnail's close button.
- Grouping: multi-selection, right-click, Ctrl/Cmd+G, and Ctrl/Cmd+Shift+G should group/ungroup nodes. Grouping a batch root includes its placements, keeps their IDs and image references, and leaves unrelated empty groups untouched. The side panel should retain focus, previews, search and export while displaying the group tree.
- Image requests: GPT Image must omit `response_format`; single/multiple OpenAI edit references use `image`/`image[]`; Gemini sends options in `generationConfig.imageConfig`. Existing mask requests and Ark JSON requests must still work.
- Image persistence: downloadable remote results should be decoded and stored locally before use; failed HTTP responses, cancellation, or timeout must not become successful images. A remote image that can display but cannot download may remain URL-only. Workbench results and their logs should reuse the stored result rather than download it again; assets and history cleanup must remain isolated.
- Media settings: verify 1K/2K/4K/auto combined with image ratios, custom dimensions and 16-pixel alignment. Video settings should offer 480p/720p/1080p, ratios and 4–30 seconds for non-Seedance requests; Seedance must retain its own ratio, duration, sound, watermark and reference limits.
- Video modes and scripts: verify first/last-frame and all-reference requests for OpenAI/Gemini, plus automatic all-reference mode with more than two images. Existing video/audio upload controls remain in the video workbench. Saved logs must restore the selected mode. Scripts receive video/audio `File[]`, mode, image quality/background, and proxy-aware HTTP helpers; templates, editing, brief copying and theme switching should work.
- Video recovery: OpenAI, Gemini and Seedance canvas nodes should save task ID/provider and the original channel/model before polling. Refreshing or “Get task status” must query that task, not submit another generation; network errors keep the ID while a confirmed remote failure clears it. Polling remains bounded to 120 attempts (2.5 seconds between attempts; 5 seconds for Seedance). Scripted jobs have no equivalent refresh recovery. Capturing first/last/current frames must create a correctly proportioned image without moving the original player's time.
- Local proxy and WebDAV: start the documented local proxy, enable/test it in Settings, and verify model requests, model lists, media downloads, script helpers and WebDAV use it; disabling it restores direct requests. After deleting a canvas, synchronization must not resurrect an older remote copy; a newer remote edit follows the timestamp conflict rule. API keys remain browser-local.
- Agent: verify credential-bearing fragment links through project creation/selection and fragment removal after reading; split stderr credentials must be redacted and configuration permissions restricted. Pure node-reference prompts, including placement IDs containing colons, should not create duplicate prompt nodes. Agent snapshots must expose resolved placement content; prompt/config updates retain references, resource-status updates affect the root resource, and replacement/delete/move operations preserve batch rules.
- Configuration and documentation: URL credentials update only a matching normalized Base URL or create a channel, never overwrite an unrelated first channel. Check the Freestylefly source and all new Chinese/English labels. Default English docs routes, locale switching, mobile section selection and desktop contents navigation should work without changing fork repository/deployment links.

Release preparation did not run a local build, typecheck or automated tests. The version tag triggers Docker builds in GitHub Actions; these builds do not replace the manual interaction checklist above. The added Agent regression cases are included in the existing test command for manual execution.

## Existing acceptance checklist

The current release needs manual verification in these areas:

- English and Simplified Chinese documentation consistently links to `fujunchao/infinite-canvas`; Quick Start, Render, Docker, License, Security, changelog, and Codex plugin installation must not redirect users to the upstream repository.
- Docker documentation describes the main application as an nginx-hosted Vite static build, uses this fork's application and documentation GHCR images, and shows the correct local access address.
- In both application languages, inserting an image asset with a missing local file shows a localized error, while generated image and assistant text fallback titles follow the selected language.
- Legacy multi-image canvas data should normalize into a resource root plus real placement nodes: every image, primary selection, storage key, dimensions, node position, node size, and external connection must remain intact, while only the obsolete root-to-child internal connections are removed.
- Agent history created before v0.15 should continue to display legacy IndexedDB attachment previews when the new Agent metadata store has no matching attachment data.
- Canvas navigation: the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should pan from the background and real nodes should still drag independently. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one resource root plus N real image placement nodes, so generating three images shows four frames. The source keeps a single connection to the root, no internal root-to-placement connections are created, every placement independently reflects its `metadata.images[]` loading, success, or failure state, and the first successful image is mirrored by the root as primary.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image placements: retrying a failed placement should update only its referenced image resource and preserve an existing successful primary; regenerating an all-failed root should reuse surviving placement IDs, geometry, and external connections by slot while removing only excess slots; deleting a placement should remove that image only when no other placement still references it, update the count, and conservatively dissolve batches that have one image left without dropping external connections.
- Multi-image collapse and movement: collapsing the root should hide, not delete, every placement and its external connections; expanding should restore the saved positions and connections. Dragging the root, including while collapsed or inside a group, should move all placements by the same delta, while dragging or resizing an individual placement should affect only that node.
- Multi-image placement interaction: every expanded placement should behave as a normal image node with stable ID, selection, movement, ratio-aware resizing, external connections, preview, download, asset saving, retry, prompt panel, and the complete image toolbar. Choosing a placement as primary should update only the root mirror. Opening/canceling tools, prompt/config editing and derived image operations must keep its imageRef; only replacing the actual media materializes it as an ordinary image node.
- Multi-image persistence and copying: placement nodes should persist their canvas interaction data, prompt/config overrides and `metadata.imageRef`, resolve image content from the root at runtime, and share the same `storageKey` without duplicating the file. Copying or duplicating a root should include its placements and remap `batchNodeId`; copying a placement alone may keep referencing the original root. Canvas Agent move, metadata update, and delete operations must preserve the same root linkage, detach, cascading-delete, and conservative-dissolve semantics as direct UI actions. The side panel should preview resolved placements, the minimap and Select All should include only currently visible placements, and reloading the project should preserve all placement geometry and connections.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets. New messages must not depend on browser IndexedDB or text matching, while legacy IndexedDB attachments are used only as a read-only fallback when server metadata is absent.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Settings import/export, Volcengine Ark protocol handling, and WebDAV-related configuration.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.
