# Docker Deployment

## Use the published image

```bash
git clone git@github.com:fujunchao/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

The root Compose file uses the main application image published by this fork:

```text
ghcr.io/fujunchao/infinite-canvas:latest
```

Open `http://localhost:3000` after startup.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is built as a separate Next.js standalone application and is not included in the main application image.

```bash
cd docs
docker compose up -d
```

The documentation Compose file uses:

```text
ghcr.io/fujunchao/infinite-canvas-docs:latest
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## Data storage

The main application image uses nginx to serve the Vite static build. Canvases, My Assets, generation history, and AI API keys are stored in the browser by default, while prompt repositories are fetched directly by the frontend. No persistent data volume is required for this data.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/fujunchao/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

Or use `docker run`:

```bash
docker run -d -p 3000:3000 \
  -e ANALYTICS_GA4_ID=G-XXXXXXXXXX \
  -e ANALYTICS_BAIDU_ID=e8263761cc5c32f5f7a855b8203b965a \
  ghcr.io/fujunchao/infinite-canvas:latest
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
