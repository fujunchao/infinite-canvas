# 画布数据结构

本文档说明当前画布在前端本地保存的数据结构、图片文件的存储和清理方式。

## 当前存储位置

当前画布项目主要保存在浏览器本地：

- 画布项目 JSON：`localForage`，数据库名 `infinite-canvas`，storeName `app_state`，key 为 `infinite-canvas:canvas_store`。
- 我的素材 JSON：`localForage`，数据库名 `infinite-canvas`，storeName `app_state`，key 为 `infinite-canvas:asset_store`。
- 图片 Blob：单独存到 `localForage` 实例，数据库名 `infinite-canvas`，storeName `image_files`。
- 视频等媒体 Blob：单独存到 `localForage` 实例，数据库名 `infinite-canvas`，storeName `media_files`。

画布 JSON 不直接长期保存大体积 base64 图片或视频。图片节点、视频节点、助手图片和素材媒体只保存展示 URL、`storageKey` 和元信息，真实 Blob 通过 `storageKey` 读取。

## 画布项目结构

每个画布项目是一个 `CanvasProject`：

```ts
type CanvasProject = {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[];
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  viewport: { x: number; y: number; k: number };
};
```

字段说明：

- `id`：画布项目 ID，当前前端生成。
- `title`：画布名称。
- `createdAt` / `updatedAt`：ISO 字符串。
- `nodes`：画布节点列表。
- `connections`：节点连线列表。
- `chatSessions`：右侧画布助手会话。
- `activeChatId`：当前选中的助手会话 ID。
- `backgroundMode`：画布背景模式。
- `viewport`：视口变换，`x/y` 是屏幕平移，`k` 是缩放比例。

## 节点结构

每个节点是一个 `CanvasNodeData`：

```ts
type CanvasNodeData = {
  id: string;
  type: "image" | "text" | "config" | "video" | "audio" | "group" | string;
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: CanvasNodeMetadata;
};
```

通用字段：

- `id`：节点 ID。
- `type`：节点类型，内置图片、文本、生成配置、视频、音频和分组，并允许插件扩展字符串类型。
- `title`：节点标题。
- `position`：画布世界坐标，不是屏幕坐标。
- `width` / `height`：画布世界坐标下的节点尺寸。
- `metadata`：节点内容和业务状态。

`metadata` 当前常用字段：

```ts
type CanvasNodeImage = {
  id: string;
  status: "idle" | "success" | "loading" | "error";
  errorDetails?: string;
  content: string;
  storageKey?: string;
  naturalWidth: number;
  naturalHeight: number;
  bytes: number;
  mimeType: string;
};

type CanvasNodeMetadata = {
  content?: string;
  prompt?: string;
  status?: "idle" | "success" | "loading" | "error";
  errorDetails?: string;
  fontSize?: number;
  generationMode?: "text" | "image" | "video" | "audio";
  model?: string;
  size?: string;
  count?: number;
  textCount?: number;
  videoMode?: string;
  videoTaskId?: string;
  videoTaskProvider?: "openai" | "gemini" | "seedance";
  videoTaskModel?: string;
  naturalWidth?: number;
  naturalHeight?: number;
  freeResize?: boolean;
  images?: CanvasNodeImage[];
  primaryImageId?: string;
  imageBatchExpanded?: boolean;
  imageRef?: {
    batchNodeId: string;
    imageId: string;
  };
  storageKey?: string;
  mimeType?: string;
  bytes?: number;
};
```

不同节点的使用方式：

- 图片节点：`content` 是当前可展示的图片 URL，通常是 `blob:` URL；`storageKey` 指向本地图片 Blob；`naturalWidth/naturalHeight/bytes/mimeType` 保存原图信息。
- 视频节点：`content` 是当前可播放的视频 URL，通常是 `blob:` URL；`storageKey` 指向本地视频 Blob；`bytes/mimeType` 保存文件信息。
- 文本节点：`content` 保存文本内容；`fontSize` 保存字体大小；`prompt/status/errorDetails` 保存生成状态。
- 生成配置节点：`generationMode/model/size/count` 保存生成配置；上游输入通过 `connections` 计算。

## 多图资源与放置节点

多图生成采用“资源根节点 + 真实放置节点”的混合结构：

- 根节点是图片资源的权威来源，`metadata.images[]` 保存全部请求槽位、每张图片的生成状态、错误、尺寸、MIME、字节数和 `storageKey`。
- `metadata.primaryImageId` 指定主图，根节点级的 `content/storageKey/naturalWidth/naturalHeight/bytes/mimeType` 始终镜像该图片；任意图片最先成功后立即成为主图。
- `metadata.imageBatchExpanded` 保存根节点的展开/收起状态；只剩一张候选时，这个字段仍保留批次身份，普通单张生成结果不设置此字段。
- 每张候选图同时拥有一个真实 `CanvasNodeData` 放置节点。放置节点持久化 `metadata.imageRef = { batchNodeId, imageId }`、`freeResize`、`groupId` 等交互字段，以及自己的提示词草稿和生成配置覆盖值；不重复保存被引用图片的 `content`、`storageKey` 和文件元数据。
- 节点渲染、左侧元素列表、生成输入、预览、下载、保存素材和图片工具栏都在运行时从根节点对应 `images[]` 条目解析放置节点内容。

因此生成 3 张图片时，画布会创建 1 个资源根节点和 3 个真实放置节点，共显示 4 个图片框。来源连接根节点，根节点到每个放置节点保存一条 `kind: "batch"` 连线。每个放置节点都有稳定 ID，并独立保存位置和尺寸，可以直接选择、移动、缩放、建立外部连线、复制、重试和使用完整图片工具栏。

批次归属线保存到 `project.connections`，复用普通连线的选中、删除和重新连接操作，随节点位置变化，收起时与分图一起隐藏。删除连线不解除放置节点的 `imageRef`，也不影响联动移动；刷新或再次展开不得重建已删除的线。手动从主图重新连接所属分图时恢复批次线，不重复创建相同端点，也不作为额外生成参考。

展开状态写入根节点 metadata，重新打开项目时恢复。收起图片组时只隐藏放置节点及其连线，不删除节点和连线；再次展开后恢复原位置、尺寸和剩余关系。拖动根节点时全部放置节点按相同位移一起移动，即使它们当前处于隐藏状态。点击「设为主图」时，根节点采用所点分图的宽高和 `freeResize`，保留根节点左上位置，分图自身几何不变。打开或取消工具、修改提示词或生成配置，以及派生裁剪、遮罩、切图、放大或角度结果，都保留原图的 `imageRef`。只有实际替换原图媒体时才解析并解除引用，转为普通图片节点并移除对应批次线；没有其他放置节点继续引用原图时，根节点才移除对应资源。

删除根节点时会级联删除全部放置节点。删除某个放置节点时，仅在它是该图片最后一个引用后才从 `images[]` 移除资源；只剩一张候选时仍保留批次身份、张数按钮、折叠、连线和联动移动。删除最后一个放置节点时，根节点保留原来显示的图片并转为普通图片。复制或创建根节点副本时会连同放置节点、剩余内部连线和展开状态一起复制，并重映射 `imageRef.batchNodeId` 及连线端点；单独复制放置节点时允许继续共享原根节点资源和同一个 `storageKey`，只有原批次线仍存在时才一并复制该线。

画布 Agent 的操作遵循相同的主图尺寸、删线/重连和单候选批次规则：移动根节点时联动未被显式移动的放置节点；提示词与配置修改保存在放置节点；状态、尺寸和文件元信息校正更新根资源；实际替换内容才解除引用。对 Agent 发布的快照会解析候选图片内容，撤销快照则保留原始存储结构，删除根节点仍会级联删除放置节点。

打开旧版“根节点 + 子节点”项目时，会复用旧子节点 ID、位置、尺寸、存储元数据、主图、展开状态和连线，将其转换为放置节点；原有主分连线标记为 `kind: "batch"`。只有 `images[]` 但缺少放置节点的批次按确定性 ID 补齐节点。仅原来没有 `imageBatchExpanded` 字段的批次在首次初始化时补齐缺失的批次线，并默认为收起；已有该字段时，缺失连线视为用户删除，不再补回。普通单张结果不产生分图或折叠控件。

## 生成参数、组引用和视频任务

- `metadata.textCount` 独立控制文本生成次数，多次结果仍是普通文本节点，不使用 `texts[]` 候选面板。
- 组用 `metadata.groupId` 关联直接成员；作为生成输入时展开有效资源，若主图对应的放置节点已在组内，不重复计入根节点镜像。参考栏以整组为单位断开组引用。
- 视频用 `videoMode` 保存首尾帧或全能参考模式；`videoTaskId`、`videoTaskProvider`、`videoTaskModel` 在查询前保存远端任务及原渠道模型，刷新后可继续查询同一任务，不受下一次生成模型选择影响。网络失败保留任务身份，远端明确失败清除任务身份；自定义脚本仍使用原有内存结果路径，不承诺相同恢复能力。
- 项目 store 另存 `deletedProjects: { id, deletedAt }[]`，WebDAV 清单的画布域使用 `deleted` 列表携带删除标记，防止较旧远端项目复活；更新更晚的远端编辑可覆盖删除标记。这不是节点字段，也不是账号云同步。

## 连线结构

每条连线是一个 `CanvasConnection`：

```ts
type CanvasConnection = {
  id: string;
  fromNodeId: string;
  toNodeId: string;
  kind?: "batch";
};
```

连线保存端点节点 ID 和可选类型，不保存端口坐标。`kind: "batch"` 表示主分图归属，不作为模型参考输入；未设置类型的连线仍用于普通工作流引用。渲染时根据节点位置和尺寸计算路径。

删除节点时会同步删除以该节点为起点或终点的连线。图片组收起时，放置节点的批次线和外部连线只在界面中隐藏，项目数据中的连线仍然保留；删除图片组根节点时才会级联删除全部放置节点及其连线。单独删除批次线仅删除该记录，不解除图片引用。

## 助手会话结构

助手会话保存在画布项目内：

```ts
type CanvasAssistantSession = {
  id: string;
  title: string;
  messages: CanvasAssistantMessage[];
  createdAt: string;
  updatedAt: string;
};
```

消息结构：

```ts
type CanvasAssistantMessage = {
  id: string;
  role: "user" | "assistant";
  mode: "ask" | "image";
  text: string;
  isLoading?: boolean;
  references?: CanvasAssistantReference[];
  images?: CanvasAssistantImage[];
};
```

图片引用和助手生成图片也遵循同一套图片存储规则：

- `dataUrl` 字段当前可能是 `blob:` URL，也可能是旧数据中的 `data:image/...`。
- `storageKey` 存在时，以 `storageKey` 为准读取图片 Blob。
- 发送到 AI 接口前，如果接口需要 base64，会通过 `imageToDataUrl` 临时把 Blob URL 转成 data URL。

## 图片写入流程

所有新增图片应通过 `uploadImage(input)` 写入：

1. 传入 `Blob`、data URL 或远程图片 URL。
2. 下载为 `Blob`，支持取消和超时，并确认图片可解码；HTTP 失败、取消或超时不作为成功结果。
3. 生成 `storageKey`，格式为 `image:<id>`。
4. 把 Blob 写入 `image_files`。
5. 创建 `blob:` URL，并缓存在内存 `objectUrls`。
6. 读取图片宽高，返回：

```ts
type UploadedImage = {
  url: string;
  storageKey?: string;
  width: number;
  height: number;
  bytes: number;
  mimeType: string;
};
```

图片节点会通过 `imageMetadata(image)` 写入：

```ts
{
  content: image.url,
  storageKey: image.storageKey,
  status: "success",
  naturalWidth: image.width,
  naturalHeight: image.height,
  bytes: image.bytes,
  mimeType: image.mimeType
}
```

因此，`content` 只适合当前浏览器会话展示，不能作为长期文件标识；长期标识是 `storageKey`。

远程图片若无法下载、但仍能读取尺寸并显示，可保留原 URL，此时 `storageKey` 为空，不能视为已经离线保存。启用本地代理后，HTTP 下载经过本机进程转发，Blob/data URL 不受影响，项目、媒体和 API Key 的本地存储位置不变。

## 图片读取和旧数据迁移

打开画布时会执行图片补水：

- 如果图片节点有 `storageKey`，通过 `resolveImageUrl(storageKey, fallback)` 读取 Blob 并生成新的 `blob:` URL。
- 如果图片节点没有 `storageKey`，但 `content` 是旧的 `data:image/...`，会调用 `uploadImage(content)` 迁移到 `image_files`，并补上 `storageKey`。
- 助手消息里的引用图和生成图也会执行同类逻辑。

我的素材读取时也会做迁移：

- 有 `storageKey`：恢复 `coverUrl` 和 `data.dataUrl` 的可展示 URL。
- 无 `storageKey` 且保存了 base64：写入 `image_files`，然后更新素材里的 `storageKey`。

## 图片移除和清理

图片不是在删除节点时立即按节点逐张删除，而是做引用清理：

1. 删除节点、清空画布、删除画布、删除素材、删除助手会话时，会触发 `cleanupImages`。
2. `cleanupImages` 会收集当前仍被画布项目、素材和额外传入数据引用的所有 `storageKey`。
3. `cleanupUnusedImages` 遍历 `image_files` 中的全部图片。
4. 不在引用集合里的图片会被删除。
5. 删除时会同时 `URL.revokeObjectURL`，并从内存缓存 `objectUrls` 移除。

这套方式可以避免同一张图片被画布、素材或助手同时引用时误删。
